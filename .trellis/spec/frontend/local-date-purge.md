# 按时间段物理清理本机数据

## 1. 范围

用户明确要求从本机彻底清除、两次确认，而非原来的隐藏。新功能独立于旧全量清理，先沿用已结算入库及关联图片范围；未结算、出库、商品和当前库存不删。共享店铺服务器与其他设备保留，不发送删除协议。原始导出备份不自动删除，不承诺介质级安全擦除。

## 2. 接口和存储

`prepareLocalPurge({required DateTime from, required DateTime to})`返回`LocalPurgePlan`：起止时间、作用域、确切ID及fingerprints、关联图片/共享保留数、跳过原因。`executeLocalPurge(plan)`只执行被冻结且仍有效的选集，返回记录数、已删图片、共享保留及待回收数；变更抛`LocalPurgePlanChanged`，需要重新预览。

SQLite v8新增`sync_purged(kind,id)`与`local_purge_gc(path)`。purge标记仅存阻止自动重拉所需ID，不存单号、图片或业务JSON，不上传、不被恢复隐藏清除。文件回收失败保留日志，允许后续重试。

## 3. 行为契约

- 时间按单据created_at解析成本地时间比较闭区间。混合本地ISO、UTC、偏移不能按字符串直接比较。UI结束分钟包含该分钟末尾，预览和执行时间语义一致。
- 在线目标必须已有服务器ack且无dirty/outbox/未解冲突/活跃OCR；不符合者明示跳过，不能删除尚未上传的唯一副本。本地模式同样保护处理中任务。
- 同步先pauseAndDrain，持有同一实例的租约，取消、错误、退出最终成对resume。本地模式不因此创建联网服务，确认过程不长时间持DB事务锁。
- 执行事务重新校验作用域、目标内容及安全条件，后来新增记录不扩大选集。先抑制dirty触发器，再删除目标主表/明细/OCR/本单历史流水及同步meta、outbox、conflicts、abandoned、媒体副本，插入purge标记；库存余额不重算。
- 远程pull、ack/meta、冲突采纳、媒体候选/attach均不得复活已purge ID；正常推进cursor，同包其他记录和服务器库存照常处理。不能只在列表隐藏，留下完整同步JSON。
- DB删除及GC日志先提交，再删无剩余引用的实际照片。必须检查其他入库、出库、同步副本及任务引用，仅清应用管理目录的安全路径；外部路径、共享引用及引用未知均保留并准确反馈。
- 第一次确认展示范围、匹配/跳过/图片数；第二次明确仅本机物理删除、库存保留、云端和其他设备保留、恢复隐藏不能找回。第二次之前任何取消均不执行，忙碌防连点，图片失败不能显示全成功。

## 4. 错误矩阵

| 场景 | 行为 |
|---|---|
| 起止非法/无匹配 | 中文提示，不执行 |
| 未同步、冲突或处理中 | 列出跳过原因，保留唯一副本 |
| 预览后改动/切工作区 | 整笔拒绝并要求重新预览 |
| 数据库失败 | 事务回滚，照片尚未删除 |
| 文件删除失败 | 记录待回收，明确未完成，允许重试 |
| 图片仍被其他数据引用 | 保留，不损坏其他记录 |

## 5. 示例

正常：已结算并已同步的某日记录，经预览与两次确认，本机主单及JSON副本移除，独占照片回收；其他手机/服务器仍有原记录。

边界：同一图片另有出库附件引用，清理该入库记录后仍保留图片；预览后新录一张同日单据，不会被旧确认无声纳入。

错误：调用旧_hideSettled当物理清理，或先删除JPEG再希望SQLite回滚还原文件。

## 6. 必须验证

真实隔离SQLite覆盖本地/共享、时间边界与时区、冻结选集变更、库存不变、所有副本消失、无新dirty、重放/新revision/迟到媒体/恢复隐藏不复活，含服务器stock摘要的后续pull。图片跨引用、安全路径、删除失败及启动回收可恢复。Widget验证两次确认、各步取消、防重复、租约释放和变更拒绝。完整Flutter测试/分析及版本化Android构建；绝不拿用户真实数据库做删除测试。

## 7. 错误与正确对照

错误：按时间再次SELECT删除全部匹配、隐藏仍保留JSON，或只删主表任同步自动下载回来。

正确：冻结ID及指纹、事务复验、物理清理本机副本，并用最小ID标记保护所有远程写入与媒体回包路径，保留服务器和库存。
