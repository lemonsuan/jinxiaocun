# OCR开关与低占用拍摄约定

## 1. 适用范围

适用于设置OCR总开关、所有本机/远程图片识别、普通照片交接、极速持久队列及Android相机反馈。沿用[工作区约定](./remembered-workspace.md)和[相机/OCR质量规范](./quality-guidelines.md)，不更换模型、同步状态或库存规则。

## 2. 存储与接口

配置库 `app_settings.ocr_enabled` 为设备级开关，缺省开启。不得复用选择local/self_hosted的 `ocr_mode`，不得写入当前店铺业务配置导致切店失效，业务备份不覆盖该设置。

普通拍照返回不可变 `CapturedPhoto(imagePath,crop,previewAspect)`，代表已保存的正式静态原图及取景几何。普通相机页不等待整图裁剪或重编码；唯一调用方先拥有原图，再按开关处理。相机优先调度使用轻量、可嵌套、幂等释放的租约，不能另建一套照片队列。

## 3. 行为契约

- 关闭OCR后，普通、极速、历史重识别、相册及图像AI都不能启动图片识别或图片远程请求；纯文本AI保留原联网规则。只隐藏按钮不足以实现关闭，平台桥/识别服务必须检查同一设备许可。
- 许可带代际：关闭再开启也不能接纳旧请求结果。发送前、返回后以及最终商品/库存写入前校验；异步SQLite事务内取消必须整笔回滚，不留下部分库存。保留已有工作区、原图路径、job token和单据状态的保护。
- 关闭期间新单仅保存单号和原图，使用现有 `needsReview` 显示待补录，无自动识别任务；手工商品可继续填写。不能以空商品标识别成功或伪造库存。
- 旧pending保留并暂停，开启后仅恢复原pending。关闭期间新单不能因为开启而自动加入旧队列；用户可主动重新识别。
- 关闭或取消不等于识别失败，不把原pending写failed、不清旧商品、不删除原图。正在native Run期间不得强制释放句柄；安全收尾后沿用空闲释放。
- 普通/极速相机页存活时，后台队列不启动下一项裁剪/OCR；现有在跑项安全结束。进相机不等待排空；退出后唤醒队列，但OCR总开关仍优先。显示“退出拍摄后识别”或“识别已暂停”，不虚报正在识别。
- 普通图片开启OCR后以一次后台处理统一EXIF方向、框裁剪及JPEG编码；不按宽大于高猜测旋转，不用PNG覆写JPG。关闭时保留原JPEG和EXIF，无不必要完整像素处理。
- 正式照片保留现有清晰度约束。Android支持且非低RAM时尝试ZSL，绑定失败可同画质单次回退；不支持或低RAM沿用低延迟模式。不能把模式名当作真实曝光延迟或缓存占用的测量。
- 所有拍照去掉全屏闪白及亮度闪烁。仅照片有效保存之后允许一次轻触觉、局部按钮勾及“已拍好，可以移开”；入库事务提交之后才称已录入。反馈不能额外阻塞下一单。拍摄开始事件只计时，不能当保存成功。

## 4. 错误矩阵

| 条件 | 处理 |
|---|---|
| OCR关闭或许可代际过期 | 阻止新调用/丢弃旧结果，保留照片与既有数据 |
| 设置持久化失败 | 中文错误，不让UI状态与底层实际开关悄悄不同 |
| 裁剪/识别失败 | 原图可查可重试，不称拍照已丢失 |
| 保存失败/过期捕获回调 | 不成功勾、不成功触觉，不提交错单 |
| ZSL不支持/低RAM/绑定失败 | 同画质低延迟模式，不无限重试 |
| 页面退出或取消/前后台 | 释放正确租约及相机资源，迟到结果不覆盖新草稿 |

## 5. 示例

正常：低端设备关OCR→扫描单号→正式拍摄→原图保存后轻反馈→needsReview待补录；重启和切店仍关闭，无模型调用。

基础：已有pending→进入拍摄页面暂不启动新任务→退出页面且开关开启后继续；关闭再开启期间旧结果失效，旧任务可重新调度。

错误：开关只控制按钮却仍kick原队列；开关关闭触发catch后把单据写failed；按快门就成功震动；为提速用预览帧或移除可靠落盘。

## 6. 必须验证

真实临时SQLite验证设备设置、重启/切店及备份隔离，新单状态/无任务/无库存、原pending保留恢复、事务取消回滚。MethodChannel与HTTP mock验证off零图片调用、off→on拒旧结果和纯文本AI正常。租约验证嵌套/幂等释放/唤醒及总开关优先。相机验证延迟/失败无提前成功、取消和下一单无旧反馈、原图及JPEG方向裁剪、ZSL决策和单次回退。

完整Flutter测试与静态分析、Android JVM/Kotlin及release构建为代码门槛。相同手机各至少20次，分别记录普通/极速、OCR开关、日光/暗光的中位数/P95、失败、清晰度与成功后移动样张；无真机不得声称已达到系统相机速度。

## 7. 错误与正确对照

错误：`takePicture → Dart裁剪重编码 → 返回 → 再整图纠正方向 → OCR`，或将 `captureStarted` 当可以移开。

正确：`takePicture正式照片保存 → 轻反馈并交原图/几何 → 调用方先持有原图 → 开启OCR时单次后台处理`，极速同样以可靠保存事件反馈并优先继续拍摄。
