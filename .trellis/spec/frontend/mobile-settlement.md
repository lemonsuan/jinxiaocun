# 手机结算标记与刷新协调

## 1. 范围

手机入库历史及核验车标记已结算/未结算。它是入库单本机字段修改，与Web给拍手订单确认返款的版本核对/资金记录不是同一功能。结算标记不写库存、不处理图片或OCR，不等待网络。

## 2. 数据接口

`LocalInventoryDatabase.setReceiptSettled(receiptId,isSettled)`保留单条兼容入口，批量接口`setReceiptsSettled(receiptIds,isSettled)`使用同一事务。去重且空集合不写入；按SQLite参数上限分片，所有目标必须存在，后段失败回滚整个事务。保留既有同步dirty触发器，不修改schema或库存流水。

## 3. 页面与异步契约

数据库保存成功后按确切ID局部替换当前receipt的isSettled，保留当前其他字段。不能await库存/入库/出库全量重读，不能重载每张单据商品来完成按钮反馈；失败不显示新状态。单条防同ID并发，批量冻结选集，防连点。

核验车使用自己的可变列表或重新赋值，不就地修改外部可能为const的allReceipts；父回调携带目标ID和状态，执行最小批量事务并更新父内存，返回最新父列表，不调用全量refresh。更改后状态筛选和结算计数须立即正确。

刷新协调必须阻止写之前开始的旧读覆盖已提交状态，也阻止旧刷新晚于新刷新应用。不能永久保存本机覆盖表屏蔽后来合法的服务器更新；必要后台补刷新只用于保留同期库存/OCR等更新，不纳入结算按钮await链。卸载、工作区改变后不得应用迟到页面结果。

## 4. 错误矩阵

| 情况 | 行为 |
|---|---|
| 单据不存在/批量缺少部分目标 | 抛错，整笔回滚，页面不报成功 |
| 后段SQL或触发器失败 | 所有结算状态与dirty代际回滚 |
| 连点或保存中再次提交 | 阻止同一目标并发，不反复翻转 |
| 旧全量刷新晚返回 | 不覆盖新状态；允许之后正常刷新 |
| 后台补刷新失败 | 中文提示并保留已保存状态，不抛未处理异步异常，不循环重试 |
| 页面卸载/切工作区 | 旧结果不更新新页面或跨店数据 |

## 5. 示例

正常：未结算单据保存为已结算，页面对应行立即变更，dirty等待原后台同步，库存保持不变。

边界：核验车匹配1205张单据，SQL分片仍由一个事务保护，尾段失败时前段不会留下已改状态。

错误：为了让按钮变快，先显示成功再无回滚地写库；或局部修改后保留无限期补丁，导致另一台手机后来的合法更改永远不可见。

## 6. 验证

临时真实SQLite验证单条、批量、空集合、去重、缺失、分片故障回滚、dirty及库存不变。界面或实际使用的状态协调器验证延迟读取、重复点击、失败不更新、筛选、父子列表与卸载，记录结算路径不调用整库读取。完整Flutter测试/分析与Android release；没有真机不可宣称具体时延提升。

## 7. 正误对照

错误：`await setReceiptSettled(); await _refreshData();`，全量加载所有历史及商品后按钮才改变。

正确：等待最小事务成功，局部更新目标行，使用有期限的刷新代际协调保护页面，继续正常后台同步。
