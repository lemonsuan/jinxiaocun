# 实施计划

本子任务为用户追加的数字店铺ID要求，用户已完成最终确认并授权自行开发，按计划实施。

1. 后端实施者负责Shop字段/分配器/迁移、旧店补号、创建/my-shops/加入兼容接口与测试。不得破坏既有库存/作业权限或原UUID关联。
2. 数字契约完成后供作业后端/前端实现使用；作业拍手注册/登录强制shop_number数字上下文。批量查单按旧鉴权内部id运行，与数字显示无耦合。
3. Web实施者改ShopSelect/ShopLayout显示与输入（与jobs前端共享文件先定所有权），Flutter实施者只改Login数字申请/展示和对应测试，不改业务库scope。
4. 隔离迁移测试旧店号码稳定和字段回填；真实PostgreSQL并发建店不重号；新旧加入payload与编号非法测试；Flutter工作区原104项及数字申请回归。
5. 受控备份本机开发库后迁移，验证用户现有admin/店铺/库存仍在；浏览器数字ID显示与拍手注册闭环、模拟器旧缓存不变。
6. 代码检查、前端构建/Flutter构建；递增Web和App版本，产物根releases归档，本地提交并记录兼容结果。

追加验收：管理页复制店铺数字ID注册URL，手机打开直接注册并显示正确店名；测试Clipboard拒绝/不可用回退、链接不含凭据、未知/篡改编号失败、已禁用账号不可绕过。部署公开Web基址可配置，分享链接不要硬编码localhost。
