# 实施计划

用户已授权总任务规划并自行推进；本子任务业务需求明确，规划写入后可独立进入实施，不等待作业账号/报名规则决定。主会话先核对计划和接口，再派发实施。

1. 后端实施者负责batch查询service/router及测试，仅当前店铺、精确去重匹配、整批汇总+独立分页、限界查询；路由顺序避免动态id捕获batch。
2. 前端实施者负责新增批量组件/API类型/入库入口，复用鉴权图片和现会话scope保护；当前job-reporting子任务将改导航/auth及新增作业页面，文件责任需明确协调。
3. Django隔离测试覆盖多号/重复/缺失/分页总计/无编码/跨店/归档和鉴权，加入查询数量断言；Vue纯函数测试输入解析和合计数据呈现，构建含TS检查。
4. 浏览器在隔离服务造多单据与照片，真实粘贴多号/查图/查看汇总/切店，手机和桌面截图验证；保留正在运行的用户5173/8000。
5. 检查代理独立复核数据权限、汇总与分页契约；修复后更新中文规范与记录，主会话按总任务版本化归档前端和本地提交。

验证：backend/manage.py test --settings=shop_sync_backend.test_settings（只隔离库），npm --prefix frontend test，npm --prefix frontend run build。涉及共享auth/路由的变更须回归既有同步与会话隔离测试。
