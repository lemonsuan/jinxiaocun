# 同店铺多手机增量同步、本机删除隔离与在线查看

## Goal

检查并补齐店铺全流程，让多台手机登录同一店铺后同步新增及修改的数据。用户已将最初的“传播删除”要求改为：**一个App删除，其他App不删除；只能增量同步；服务器保留数据并可在线查看**。用户明确要求“创建任务并规划，自行推进”，授权完成规划后自主实施，不再重复询问阶段确认。拍照和OCR任务保留待真机验收。

## Confirmed Current Gaps

- 移动端只有登录/选店及服务器地址配置，没有Push/Pull调用；本地业务表无店铺隔离，切店可混用数据。
- 本地记录使用in-/out-/lg-时间ID，现有服务端同步Schema要求UUID，协议无法直接兼容。
- 现有服务端推送无版本冲突或重试幂等，直接接受客户端库存覆盖；关联明细缺少跨店铺父记录校验。
- 服务端入库删除会硬删除单据/明细/流水，与留存要求冲突；网页仍是编辑维护界面。
- 图片仅保存手机私有路径，没有上传/受保护下载，其他手机和网页无法查看；自动化测试主要为占位或一次性冒烟。

## Requirements

- R1：注册/登录、创建/申请加入店铺、审批与选店形成完整流程。只有已批准成员访问同店铺数据，切换账户/服务器/店铺不得串数据或提交旧任务。
- R2：新增和修改通过持久化待同步队列及服务器版本游标增量传输。网络失败、超时、重复发送、应用重启不丢失数据，不全库覆盖；不发送任何删除操作。
- R3：在线模式下删除/清理属于本机隐藏或缓存清理，不撤销店铺库存、不修改其他手机或服务器。隐藏标记仅本机持久化，增量拉取不使其重新显示；可显式恢复本机显示。未上传数据不能因清理丢失。离线独立工作区仍保留原有业务行为。
- R4：服务器完整留存接收的记录、图片和操作结果；禁止旧库存写/硬删除接口绕过留存。同步采用幂等与版本检查；冲突明确保留并可查看，不能静默用旧手机覆盖新记录或把冲突报告为同步成功。
- R5：库存由业务单据变更及服务端只读汇总保持一致，不接收手机整份库存覆盖；并发/重复请求不重复记账，库存不足或重复单号冲突不能形成已确认的错误结果。
- R6：图片可按店铺鉴权上传、去重和下载；其他手机及网页可实际查看图片，不使用另一手机沙盒绝对路径，也不公开跨店铺文件。
- R7：服务器及Web聚焦同步留存与只读查看：商品、入出库详情、库存、流水、图片可分页/搜索/按日期及结算状态筛选，账户与店铺成员管理仍可用；库存数据不提供网页删改。
- R8：原有本地数据及既有服务器数据保留；迁移明确归属现有激活工作区，不自动把本地默认店铺数据发给任意新店铺。备份不复制认证凭证、设备身份、游标、待发操作或本机隐藏状态到其他手机。
- R9：覆盖两套独立手机数据库、服务端API、Web查看的集成验证，包含只增量、不传播删除、重试、切店、冲突与跨租户拦截。交付版本化APK及本地Git提交，未部署/无真机的部分如实说明。

## Acceptance Criteria

- AC1 / R1：两账号同店审批通过后可同步，未批准/其他店成员不能读写数据或图片；切店后只出现该店数据，旧请求不能写入新工作区。
- AC2 / R2、R4：A新增/修改→服务端→B增量可见；操作重试不重复记录/库存；断网重启后继续；旧版本更新返回冲突且本地保留待处理内容。
- AC3 / R3、R4：A隐藏入库/清理后，B和服务器原记录/图片/库存仍在；A多次同步或重启后仍隐藏，显式恢复后可见；不发送删除或伪造库存回退。
- AC4 / R5：双端并发、重复单号、库存不足和价格/数量非法数据均有测试；同步库存汇总不接受客户端覆盖，不重复计算单据。
- AC5 / R6、R7：Web可查看手机同步的记录与图片，列表分页/筛选稳定；图片鉴权、内容哈希及大小校验通过；服务器不因客户端清理删除文件。
- AC6 / R8：遗留SQLite/服务器迁移与旧备份恢复有回归；原数据不丢失/串店；内部同步状态不随备份转移。
- AC7 / R9：移动端测试、后端测试、Web类型/构建及浏览器流程通过，新增失败修复；真实手机/线上部署若不可用则标为待验，不把模拟验证称为已上线。

## Out of Scope

部署到未提供地址的生产服务器、支付/电商/物流平台集成、实时推送基础设施、删库或批量清理旧服务器数据、修改OCR模型和拍照模块。多个离线设备同时消耗同一库存不能保证物理零超卖；服务端必须检测同步冲突并保留待处理信息。
